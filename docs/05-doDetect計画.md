# OhmLens — doDetect.sh（バッチ検出デバッグ）の計画

2026-07-27 作成。**実装済み。** 実行結果と所見を末尾に記載。

## 目的

検出のデバッグを 1 コマンドで回せるようにする。

```bash
./doDetect.sh
```

- `sample/` の抵抗器写真を**すべて**読み込み、**1 枚ずつ**処理する
- 元画像に検出結果をオーバーレイした画像を `sample-detect/` に保存する
- オーバーレイの内容:
  1. 検出した抵抗器を囲む**赤い回転四角形**
  2. 各バンドの**色名**（赤・白・茶 …）
  3. 各バンドの**カラーコードとしての意味**（0, 1, 2, ×10, ±10% など）

## 既存資産との関係

D1〜D3（docs/04）で大半の部品は揃っている。**新規実装は薄い**。

| 必要なもの | 状態 |
| ------------ | ------ |
| 検出 → 解析 → 焼き込みの一連 | ✅ `annotate.test.ts` にある。ただし vitest 内・出力先 `debug-out/`・英字ラベルのみ |
| 座標変換（回転四角・バンド位置） | ✅ `core/roiMapping.ts` |
| 色名の日本語表記 | ✅ `BAND_COLOR_JA` |
| 日本語フォント（sharp/pango） | ✅ この環境に CJK フォントあり（fc-list で 86 件確認） |
| **バンドの意味（数字/倍率/許容差）の割り当て** | ❌ 無い。今回の本体 |
| CLI ランナー | ❌ 無い（`tsx` を devDependency に追加） |

## 構成

「シェルスクリプトは本プロジェクトの関数を呼び出す」という要件どおり、
ロジックはすべて TypeScript 側に置き、シェルは薄い皮にする。

```text
doDetect.sh                     … 前提確認・進捗表示・引数の受け渡しだけ
  └→ npx tsx scripts/annotate.ts --in ../sample --out ../sample-detect
       └→ core の関数をそのまま使う:
          loadImage(sharp) → locateResistor → rectify → analyzeRoi
          → roiMapping（bandCorners / labelAnchor）→ SVG 合成で焼き込み
```

- `scripts/annotate.ts` は **`annotate.test.ts` から抽出**して共通化する。
  テストは同じ関数を `debug-out/` 向けに呼ぶだけにし、二重実装を避ける
- 1 枚ずつ逐次処理し、1 行ずつ進捗を出す
  （`03/39 11-220ohm-5pct.jpg 期待 220Ω → 220Ω  24° 比3.2  赤2 赤2 茶×10 金±5%`）
- 1 枚の失敗（読込不可・検出失敗）で止めない。失敗も
  「検出失敗」を焼き込んだ画像として出力し、最後に集計を出す

## ラベルの意味付け（今回の実装の本体）

「色名」だけでなく「その色が何を意味したか」を出すには、
**デコーダがどのランをどの役割で使ったか**が要る。

現状の `jointReadResistor` は最終的な値しか返さず、
「どのランを数字/倍率/許容差に使い、どのランを捨てたか」を捨てている。

### 変更: jointDecode が採用割り当てを返す

```text
ResistorReading に加えて（または JointResult として）:
  usedRuns: { runIndex, color, role, roleText }[]
    role: 'digit' | 'multiplier' | 'tolerance' | 'tempco'
    roleText: '2' | '×10' | '±5%' | '50ppm' など
  direction を反映済み（runIndex は入力順のまま）
```

- 探索で best を確定した時点の `keptIndices` と方向から機械的に作れる
- 役割の値は既存の `codeTable`（digitOf / multiplierOf / toleranceOf /
  tempCoefficientOf）から引く。表を増やさない
- 単体テストで固定する: 4/5 バンド・逆向き・ラン除去ありの各ケースで
  `usedRuns` の役割列が期待どおりであること

### 表示規則

- 採用されたラン: `色名 + 意味` の 2 行（例: 上段「赤」下段「2」、
  倍率は「×10」、許容差は「±5%」）
- 採用されなかったラン（ノイズとして捨てられた）: 色名のみ + 取り消し風の
  薄表示。**捨てた事実が見える**ことがデバッグでは重要
- 読み取り自体が失敗（reading=null）: 全バンド色名のみ
- 下部のキャプションバーに集約情報
  （ファイル名 / 期待値 → 検出値 / 角度・長さ・太さ・比 / バンド列）

## 出力先と後始末

- `sample-detect/` は `~/44-ohm-lens/`（外側リポジトリ）直下。
  生成物なので外側の `.gitignore` に追加する（再生成可能なため）
- 再実行時は既存ファイルを上書き。`--clean` で事前に空にできるようにする
- 期待値はファイル名と `sample/MANIFEST.json` から引く（無い画像は
  「期待 不明」として処理は続行）

## doDetect.sh の仕様

```text
./doDetect.sh            # sample/ → sample-detect/ 全件
./doDetect.sh 11         # ファイル名に "11" を含むものだけ（1 枚デバッグ用）
```

- `node_modules` が無ければ npm install を促して終了
- 終了時に集計（処理 N 枚 / 検出失敗 M 枚 / 値一致 K 枚）と出力先を表示
- 失敗が 1 枚でもあっても exit 0（デバッグツールなので、失敗の可視化が仕事）

## 注意点

- 意味ラベルは**デコーダの解釈**であって正解ではない。誤読のときは
  「間違った解釈がそのまま表示される」——それこそが見たいもの、という
  位置づけを README に明記する
- 日本語フォントはこの環境にはあるが、他環境では `--ascii` で
  英字 3 文字 + 記号（2 / x10 / ±5%）にフォールバックできるようにする
- HEIC 等 sharp が読める形式はそのまま対象。読めないファイルはスキップし
  集計に「読込失敗」として出す

### 表示例

```text
11-220ohm-5pct.jpg | 期待 220Ω → 5.1kΩ | 24° L261 T110 (比 2.38)
  | red±2% red×100 brown1 green5
```

画像上は「赤 ±2%」「赤 ×100」「茶 1」「黄 5」が色玉つきで並び、
除外されたランは破線 + 「除外」で表示される。

### 所見: 意味ラベルで誤読の性質が分かるようになった

`11-220ohm`（期待 220Ω）の解釈は `red±2% red×100 brown1 green5` だった。
つまり**方向を逆に読み**（許容差を左端に置き）、さらに本来 3 本しか無い
バンドに 4 本目（green）を拾っている。色名だけを見ていた頃は
「赤赤茶が取れているのに値が合わない」までしか分からなかったが、
役割まで出すと**方向判定とラン過検出の複合**だと即座に分かる。

`22-3.3kohm`（正解）では `orange3 orange3 red×100` と読み、4 本目の白を
「除外」と表示している。捨てた判断が正しかったことも見て確認できる。
