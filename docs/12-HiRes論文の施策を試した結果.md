# OhmLens — HiRes 論文の施策を試した結果

2026-07-28 作成。抵抗器カラーコード読み取りの先行研究を調べ、最新の
HiRes 論文（[arXiv:2606.30179](https://arxiv.org/abs/2606.30179)）から
2 つの施策を移植する計画を立て、着手前の計測でどちらも否定した記録。

> **結論: HiRes の「ギャップ保存分離」と「相対幅フィルタ」は、どちらも
> OhmLens には効かない。**
> ギャップ保存は前提となる現象（同色隣接バンドの融合）が 39 枚で 1 件も
> 起きていない。相対幅フィルタは 39 枚すべてで 1 本も落とさない。
> 一方この計測の副産物として、**残り 12 枚の保留の内訳が分かった**（§4）。
> 最大の塊は「本数は合っているのに色を誤る」5 枚で、分割の問題ではない。
> その内訳をたどって、**正解 27 → 32 / 誤答 0 のまま**まで進めた（§6）。
> しきい値も 0.40 → 0.32 に下げられるようになった（§6.4）。

関連: [07-色帯読み取りの改善.md](07-色帯読み取りの改善.md) /

## 1. HiRes 論文とは

2026 年 6 月、ICONIP 2026 投稿。抵抗器の値読み取りを 3 段カスケードで解く。

1. 物体検出（YOLOv8n、mAP50 = 0.9906）
2. セマンティックセグメンテーション（UNet++ / EfficientNet-B2、
   12 色 + 背景の 13 クラスに画素分類、mIoU = 0.8444）
3. 軸に沿った射影による幾何デコード（end-to-end 85.8%、106 枚）

OhmLens が採れないのは 2 段目である。CLAUDE.md の「カラーバンド読み取りまで
NN に任せない」に真っ向から反する。したがって移植候補は 3 段目に限られる。

論文のアブレーションは、その 3 段目のどこが効いているかを数字で示している。

| 外した要素 | 精度 |
| ------------ | ------ |
| ギャップ保存分離 | 85.8% → **50.9%**（5 バンド品は 44/54 → 9/54） |
| 粗密リファイン | 85.8% → 77.4% |
| E24 系列検証 | 85.8% → **85.8%（変化なし）** |

E24 検証が効かないのは OhmLens にとって朗報で、既に
[eseries.ts](../src/core/value/eseries.ts) と同時デコードで同等以上のことを
やっている領域に伸びしろが無いことの裏付けになる。

## 2. 立てた仮説と、その根拠だったもの

`sample-report.txt`（値一致 29/39、実機 正解 27 / 誤答 0 / 保留 12）と
`sample/labels.json` を突き合わせると、次のように見えた。

- 39 枚中 **20 枚が同色隣接バンドを含む**。E24 の性質上これはふつうで、
  11 / 22 / 33 / 220 / 330 / 2.2k / 22k / 330k などがすべて該当する
- うち **7 枚で、その色が検出側では 1 本に減っている**（01 02 04 07 09 21 39）。
  しかも 7 枚すべてが保留

5 バンド品が集中している点まで HiRes のアブレーション
（ギャップ保存を外すと 5 バンド品が壊滅）と一致していた。

**この見立ては誤りだった。** 「検出側にその色が 1 本しか無い」は、
融合したときにも**別の色に誤分類したとき**にも成り立つ。両者を区別せずに
数えていた。

## 3. 計測 — どちらの施策も効かない

切り分けのために [scripts/dbgGap.ts](../scripts/dbgGap.ts) を追加した。
本番と同じ経路（本体範囲で切ってから `splitRuns` → `identifyBody`）を再現し、
次の 3 つを数える。

```bash
npx tsx scripts/dbgGap.ts ../sample/*.jpg
```

### 3.1 同色隣接バンドの融合は起きていない

疑っていた 3 枚を個別に見ると、いずれも融合ではなかった。

| 画像 | 期待 | 候補 | 実際に起きていること |
| ------ | ------ | ------ | ---------------------- |
| 01-1ohm | 5 本 | 4 | 黒黒は**2 本のランに分かれている**。欠けているのは銀（[11](11-金銀バンドが読めない理由.md) のとおり）。2 本目の黒を茶と誤分類 |
| 39-10Mohm | 5 本 | 5 | **本数が合っている**。黒黒も分かれている。誤りは分類と方向 |
| 21-2.26kohm | 5 本 | 6 | 融合ではなく**過分割**。本体の陰影が候補に混じっている |

39 枚全体では、間に本体ランを挟まずに隣り合うバンド候補を持つ画像が 17 枚
あるが、これは「1 本のバンドが陰影で 2 本に割れた」過分割側の現象で、
`mergeAdjacent` が戻すべきものである。融合が疑われるのは
`run.start - previous.end <= 1` のときだけだが、実測ではラン境界のぼけで
**どの境界でも 2〜3 列が捨てられている**ため、この条件はほとんど成立しない。

**なぜ OhmLens では起きないのか。** HiRes の問題は「クラス投票の
ヒストグラムに Gaussian 平滑（σ=2.5 bin）をかけると、同色隣接バンドの間の
物理的ギャップが埋まる」ことである。OhmLens は画素をクラス分類してから
束ねるのではなく、**先に色差でランを切ってから分類する**
（[runs.ts](../src/core/bands/runs.ts) の冒頭コメント）。平滑の段が無いので、
埋まるギャップも無い。**設計が違うので、この問題が最初から存在しない。**

### 3.2 相対幅フィルタは 1 本も落とさない

HiRes は「バンド幅の中央値の 20% 未満」を捨てる。同じ判定を 39 枚に当てた。

| 指標 | 結果 |
| ------ | ------ |
| 相対幅フィルタで落ちるラン | **0 / 39 枚すべてで 0 本** |
| バンド候補の幅の中央値 | 4〜9 列 |

過分割で増えたランは、本物のバンドと**同じくらいの幅**を持つ。21 では候補の
幅が 2〜6 列に散らばり、中央値 4 に対する 20% は 0.8 列 — 何も落ちない。
HiRes は 200 ビンに正規化した軸上で数えるので相対閾値が意味を持つが、
OhmLens は ROI の元解像度の列をそのまま使っており、そもそも過分割の
ランが細いわけではない。

## 4. 副産物 — 残り 12 枚の本当の内訳

計測の過程で、保留 12 枚が 4 つの塊に分かれることが分かった。
以下は**この時点（正解 27 / 誤答 0 / 保留 12）**の内訳である。
このうち 02 / 04 / 05 / 21 / 23 は §6 で解決し、現在は正解 32 / 誤答 0 / 保留 7。

| 症状 | 枚数 | 画像 | 候補 / 期待 |
| ------ | ------ | ------ | ------------- |
| **分類の誤り**（本数はほぼ合っている） | **5** | 01 03 09 15 39 | 4/5, 4/4, 4/5, 5/5, 5/5 |
| 重度の検出不足 | 3 | 02 04 38 | 2/4, 2/4, 1/4 |
| 確信度だけが足りない（値は正解） | 2 | 05 23 | 5/5, 5/5 |
| 過分割 | 2 | 07 21 | 7/5, 6/5 |

**最大の塊は分割ではなく分類である。** 05 と 23 に至っては値もバンド色も
正解で、確信度が 34% / 33% と閾値に届かないだけ（[09](09-色空間と色差指標の検討.md)
の指摘のとおり）。

分類の誤り方には偏りがある。39 は本体基準の色順応補正で L\* が 3.75 倍まで
引き伸ばされており（[09](09-色空間と色差指標の検討.md) §1）、黒バンドが
L20 a12 b30 と読まれて茶に倒れている。**b\* が 30 もある「黒」**は、
補正と `palette.json` の密結合が生んでいる歪みで、分割をいくら直しても
届かない。

## 5. 確信度の閾値 — 下げる前に順序を直す必要があった

§4 の「確信度だけ足りない 2 枚」を拾おうとして、しきい値
（`MIN_REPORTABLE_CONFIDENCE = 0.4`）の引き下げを検討したが、そのままでは成立しない。

保留を確信度の高い順に並べると、**誤った読み取りが正しい読み取りより上に来る**。

| 順 | 画像 | 確信度 | 値 |
| ---- | ------ | -------- | ---- |
| 1 | 01-1ohm | 0.36 | **誤**（100Ω） |
| 2 | 15-339ohm | 0.35 | **誤**（330mΩ） |
| 3 | 05-7.5ohm | 0.34 | 正 |
| 4 | 23-3.9kohm | 0.33 | 正 |

しきい値を 0.33 まで下げると 05 と 23 は拾えるが、01 と 15 も同時に入って
**誤答が 0 → 2 になる**。CLAUDE.md の「誤った値を自信ありげに出さない」に反する。

内訳（`scripts/dbgConfidence.ts`）を見ても 4 枚は分離しない
（absolute 0.63〜0.71、margin 0.13〜0.23、meanΔE 11.8〜14.9）。
**必要なのはしきい値ではなく確信度の順序そのものの改善**である。

### 5.1 順序は並びの幾何で直せる

色の指標では分離しないが、**バンドの並びの幾何**では分離した。IEC 60062 は
数字・倍率バンドを等間隔に印刷し、許容差バンドだけを離す。39 枚を測ると:

| 指標 | 正解の最大 | 採用値 | 引っかかる誤読 |
| ------ | ------------ | -------- | ---------------- |
| 数字・倍率バンドの間隔の変動係数 | 0.33（29-22kΩ） | **0.40** | `01-1ohm`（0.50） |
| 許容差の間隔 ÷ 数字・倍率の間隔 | 2.44（13-330Ω） | **4** | `15-339ohm`（8.00） |

どちらも正解側と誤読側が重ならない。引っかかる 2 枚がちょうど 01 と 15 で、
確信度に 0.7 を掛けると順序が正しくなる。

| 画像 | 導入前 | 導入後 |
| ------ | -------- | -------- |
| 05-7.5Ω（**正**） | 0.34 | 0.34 |
| 23-3.9kΩ（**正**） | 0.33 | 0.33 |
| 03-1.6Ω（誤） | 0.31 | 0.31 |
| 01-1Ω（誤） | **0.36** | **0.25** |
| 15-339Ω（誤） | **0.35** | **0.24** |

**保留のなかで、正解が誤読より上に並ぶようになった。**
コストではなく確信度に掛けるのは、解釈を選び直しても直らないため —
取りこぼしたバンドは戻ってこない。

### 5.2 この時点ではまだ下げられない

順序が正しくなったので、しきい値 0.32 なら 05 と 23 を拾える。実測でも
**正解 31 / 誤答 0 / 保留 8** になる。それでもこの時点では採らなかった。

正解の下限と誤読の上限の差が **0.018 しかない**（`23` 0.3269 対 `03` 0.3087）。
[11](11-金銀バンドが読めない理由.md) が `edgeΔE 16` を「誤答 0 になる組が
一点だけで、隣が誤答 1〜2 に転ぶ」として退けたのと同じ形で、パレットが少し
動けば `03` が誤答に変わる。

境界を決めていたのは `03` の 1 枚だけだった。**その `03` を下へ動かせば
話が変わる**（§6.3・§6.4）。

## 6. 実際に効いたこと

### 6.1 ランが 2 本のときの拾い直し

§4 の「重度の検出不足 3 枚」のうち 02 / 04 は解決した。詳細は
[11](11-金銀バンドが読めない理由.md) §3.5.2。要点だけ:

- 02 / 04 は**金が倍率バンド**（×0.1）で、金の欠落が値に直結する
- 原因は分類ではなく**ラン分割**。金と本体の CIE76 が 18 前後で、全体の
  しきい値 20 に届かず本体ランに飲み込まれていた
- ランが 2 本の写真は `MIN_BANDS` に届かず必ず読取不可なので、**既に読めて
  いる写真を壊しようがない**。[11](11-金銀バンドが読めない理由.md) §3.5.1 が
  否定した「位置からの推測の一般化」の制約は、ここには当てはまらない
- 結果: **正解 27 / 誤答 0 / 保留 12 → 正解 29 / 誤答 0 / 保留 10**

### 6.2 本体基準を色みだけで選ぶようにした

`03` の誤読を追ったところ、**色順応補正が青バンドを灰に潰していた**。
`03` の 3 本目は写真では明確に青だが、`L65 a-6 b1` と無彩色に測れる。
本体アンカー `L45 a1 b6` が `beige` に写され、`b*` に **+18** が加算されるためで、
素の値 `b*-19.6` が中和されていた。

`nearestBodyReference` は ΔE2000 で基準を選ぶが、そこに**明度が入っていた**。
39 枚のアンカーを測ると、基準への倍率は 1.10〜3.75 倍に散らばり、しかも
**全枚数で 1 より大きい**（撮影されたボディは基準より必ず暗い）。
つまり明度差が測っているのは色ではなく**露出**である。

実害は `03` より `39` の方が大きかった。`39-10Mohm` は青メタルフィルムなのに、
アンカー `L20 a-7 b-5` と lightblue の明度差 59 が効いて **beige** が選ばれ、
`b*` に **+29** が乗っていた。[11](11-金銀バンドが読めない理由.md) 以降ずっと
「黒バンドが `L20 a12 b30` と読まれて茶に倒れる」と観測していた原因がこれ。

明度を基準側にそろえてから ΔE2000 で比べるようにした（`core/color/anchor.ts`）。
色相・彩度の重み付けは ΔE2000 のまま使いたいので、指標そのものは変えない。

**パレットの再学習が必須。** [09](09-色空間と色差指標の検討.md) の
「変換と palette は密結合していて、片方だけの A/B は意味を持たない」がそのまま出た。
補正だけ直すと `39` が確信度 41% の**誤答**になる。
`tests/fixtures/calibrate.test.ts` で `sample/palette.json` を学習し直すと消える。

| 指標 | 導入前 | 導入後 |
| ------ | -------- | -------- |
| 実機での見え方 | 正解 29 / 誤答 0 / 保留 10 | 正解 29 / 誤答 0 / 保留 10 |
| 正解の下限と誤読の上限の差 | 0.0182（23 対 03） | **0.0309**（05 対 03） |
| `23-3.9kΩ` の確信度 | 0.327 | **0.364** |
| `39` のバンド色 | brown green black **brown** brown | brown green black **black** brown |

**成績は動かない**が、正解と誤読の隔たりが 70% 広がり、`39` の黒バンドが
初めて黒と読まれた。§5.2 のしきい値の余地も 0.018 → 0.031 に広がった。

### 6.3 本体色の基準を 2 色から 4 色に増やした

§6.2 で補正の選び方は直ったが、`03` の読みは変わらなかった。**基準そのものが
足りていない**。`BODY_SRGB` は beige と lightblue の 2 色しか持たず、
`03` の灰白ボディ（アンカー a1 b6）には該当が無い。

素の本体アンカーを 39 枚ぶん測ると、色みは 4 系統に分かれる。

| 系統 | アンカーの a\*b\* | 該当 | 実物 |
| ------ | ------------------ | ------ | ------ |
| beige | a12〜19 b14〜27 / a0〜3 b25〜43 | 30 枚 | 炭素皮膜 |
| lightblue | a-15〜-5 b-22〜-5 | 01 05 23 39 | 金属皮膜 |
| **greywhite** | a1 b6 | 03 | セメント |
| **olive** | a-10 b10 | 21 | 金属酸化皮膜 |

`greywhite` だけを足すと **`21` が確信度 41% の誤答になった**。写真を見ると
`21` のボディは灰白ではなく**オリーブ**で、灰白に寄せたこと自体が誤り
だった。`olive` も足すと誤答は消え、しかも **`21` が正解になった**
（`brown±1% brown×10 blue6 red2 red2` = 2.26kΩ）。

**基準色は成績合わせで足すものではなく、実物の系統に合わせて足すもの**という
教訓が出た。`21` を写真で確認せずに `greywhite` の当たり判定だけを調整して
いたら、間違った基準のまま数字だけ合わせることになっていた。

### 6.4 しきい値を 0.40 → 0.32 に下げた

§5.1・§6.2・§6.3 の 3 つで確信度の順序が入れ替わり、**正解の下限 0.3276
（`21`）と誤読の上限 0.2726（`01`）のあいだに 0.055 の空きができた**
（当初 0.018、§6.2 のあと 0.031）。

| しきい値 | 0.30 | **0.32** | 0.34 | 0.40 |
| ---------- | ------ | ---------- | ------ | ------ |
| 正解 | 32 | **32** | 31 | 29 |
| 誤答 | 0 | **0** | 0 | 0 |
| 保留 | 7 | **7** | 8 | 10 |

空きのなかで**誤答側に余裕を取って 0.32** を採った（誤読まで 0.047、
正解まで 0.008）。正解を落とすのは「読めない」と言うだけだが、誤読を通すのは
自信ありげに間違えることなので、危険な側に余裕を置く。

## 7. 次に見るべきところ

- **残る保留 7 枚** — 01 03 07 09 15 38 39。うち `15` は CG イラスト、
  `38` はランが 1 本しか出ない
- **`07` の本体色** — アンカー a25 b3 で、4 系統のどれとも合わない（カーペット
  の上で撮った赤みの強い 1 枚）。5 つ目の基準が要るかは 1 枚では判断できない
- **`03` の色の誤読** — 確信度は 0.31 → 0.15 まで下がり、しきい値の障害では
  なくなった。読みは `orange3 white9 orange×1,000` で、期待の茶-青-金とは
  依然まるごと違う
- **色順応補正とパレットの密結合**（01 39 ほか）— [09](09-色空間と色差指標の検討.md)
  が「片方だけの A/B は意味を持たない」と結論した箇所。両方を同時に
  差し替える実験計画が要る
- **38 のラン 1 本** — 02 / 04 と同じ根（`edgeΔE = 20` が本体との差 18 前後の
  金バンドを切れない）だが、ランが 1 本では刻みが求まらず
  `recoverFromPair` が効かない。本体範囲 83 列のうち 6 本が本体ランで、
  L60〜96 と幅広く本体扱いされている

  — HSI 色空間での分割
