# OhmLens — 検出デバッグ表示の計画

2026-07-27 作成。**計画のみ、実装は未着手。**

## 目的

抵抗器の検出（位置・角度・バンド分割）が悪い。ところが今の GUI では
検出結果が「ROI 画像」「バンド表」「プロファイル帯」に分かれて表示され、
**元の写真のどこを何と見なしたか**が一目で分からない。

デバッグの第一歩として、静止画の上に検出結果をそのまま焼き込む:

1. 抵抗器を**赤い四角**で囲む。四角は抵抗器の角度に合わせて**斜め**にする
2. 認識したカラーコードの色名を、**各バンドの真上にオーバーレイ**する
   （例: `茶 緑 紫 黒 茶`）

これで「検出が外れているのか」「バンド分割が外れているのか」
「分類が外れているのか」を写真 1 枚で切り分けられるようにする。

## 現状の確認結果

| 項目 | 状態 |
| ------ | ------ |
| 回転ボックスの描画 | ほぼ有り。`drawDetectedBox` がピンク枠を描いている → **赤に変更するだけ** |
| バンドの座標系 | `Band.start/end` は **ROI の列番号**。extent でスライスしても `x` は振り直されないので、そのまま逆変換に使える（確認済み） |
| ROI → 元画像の逆変換 | **無い**。`rectify` は順方向（元画像 → ROI）のみ。ここが実装の本体 |
| 色名の日本語表記 | 無い。英語名のみ |

## D1: 座標の逆変換（core、TDD）

`rectify.ts` に逆変換を追加する。

```text
roiToImage(box, options, roiX, roiY) → { x, y }  // 元画像の座標
```

- `rectify` の順変換（scale / padding / 回転）を逆にたどるだけ。
  順変換と同じ定数を共有し、式の二重管理をしない
- テストは**往復**で固定する: 元画像の点 → (順変換の式で) ROI の点 →
  `roiToImage` → 元の点に戻る（角度 0 / ±30° / パディング有無 / 拡縮有無）
- ついでにバンド 1 本ぶんの補助も用意する:
  `bandCorners(box, options, band)` → バンド領域の四隅（元画像座標）。
  ラベル位置の計算（バンド中心の法線方向上側）もここに置き、
  描画コードから座標計算を追い出す（テスト可能にするため）

## D2: GUI オーバーレイ（静止画）

`analyzeSelection` の描画に追加する。対象は読み込んだ静止画
（カメラの静止化画像を含む。ライブ映像も同じコードで動くが、確認は静止画で行う）。

- **赤い回転ボックス**: 既存 `drawDetectedBox` の色を `#ff3b30` 系の赤へ。
  線幅は画像サイズに比例（現状の式を踏襲）
- **バンドの帯**: 各バンドの範囲を半透明の縦帯（回転に追従）で塗る。
  検出色をそのまま使うと写真と紛れるので、白の半透明 + 検出色の縁取り
- **色名ラベル**: バンド中心から法線方向（短軸の外側）にオフセットした
  位置に、**水平の日本語 1 文字**（黒/茶/赤/橙/黄/緑/青/紫/灰/白/金/銀）を描く
  - テキストは回転させない（読みやすさ優先）
  - 白フチ + 黒文字（`strokeText` → `fillText`）でどんな背景でも読めるように
  - バンド間隔が詰まって重なる場合は上下交互に段違い配置
  - フォントサイズは箱の太さに比例させ、小さすぎる場合は下限を設ける
- 確信度が低いバンドはラベルを半透明にする（誤分類が視覚的に分かる）
- 手動 ROI モード（自動検出オフ）のときは、角度 0 の箱として同じ経路で描く

## D3: 全サンプルの一括アノテーション出力

GUI で 1 枚ずつ見るのは遅いので、**39 枚全部に焼き込んだ画像を一括生成**する
ハーネスを足す（Node / sharp。SVG オーバーレイを合成できる）。

- `npm test -- annotate` で `debug-out/`（git 管理外）に
  `01-1ohm-….annotated.jpg` … を出力
- 内容は D2 と同じ: 赤い回転ボックス + バンド帯 + 色名
- ファイル名に期待値が入っているので、画像を開けば
  「期待 1Ω / 検出 茶黒黒赤」のずれが一目で分かる
- ImageMagick `montage` で一覧シート化するおまけスクリプトを添える
  （検出の失敗を 1 画面で俯瞰する用）

D1 の座標計算を共有するので、GUI と一括出力で結果がずれることはない。

## 受け入れ基準

- [ ] 斜めに写った実写（例: `11-220ohm-5pct.jpg`、24° 傾き）で、赤い四角が
      抵抗器に沿って斜めに表示される
- [ ] 色名ラベルが**写真上のバンドの真上**に載っている（表と突き合わせて
      位置ずれがない）
- [ ] 往復テストで座標変換の誤差が 1px 未満
- [ ] `npm test -- annotate` が 39 枚を出力し、目視で検出品質を評価できる
- [ ] 検出失敗（box=null）の画像は「検出失敗」の焼き込みで出力される

## 注意点

- ラベルの日本語 1 文字表記は「銀/灰」「金/黄」が紛らわしいので、
  ラベル背景に検出色のスウォッチ（小さい色玉）を添える
- sharp の SVG 合成では日本語フォントが環境依存。一括出力側は
  英字 3 文字（BLK/BRN/RED/ORG/YEL/GRN/BLU/VIO/GRY/WHT/GLD/SLV）に
  フォールバックできるようにする
- ライブカメラで常時オーバーレイすると描画コストが乗るが、対象は静止画の
  確認なので今回は最適化しない（M4 のオーバーレイ設計に引き継ぐ）
