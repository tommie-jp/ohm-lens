# OhmLens — スマホ対応計画

2026-07-27 作成。M0 前提・M1・M2・M3.1 は実装済み（下の実装状況を参照）。

## 目的とスコープ

学習ループ（抵抗を映す → 値を打つ → その場で賢くなる）を**スマホ実機で
快適に回せる**ようにする。OhmLens の本来の利用シーンは「工作机でスマホを
かざす」なので、これはデバッグページの延命ではなく本番 UI（ロードマップ
Phase 1）への足場でもある。

やらないこと:

- 本番ドメインへの移行・ホスティング整備（設計メモ §8、別トラック）
- ネイティブアプリ化（PWA まで）

## Phase M1b: UI の作り直し（2026-07-27）

「使いづらい」との指摘を受け、レイアウトを作り直した。それまでの構成は
**パイプラインの各段を上から並べたもの**（1.入力 → 2.結果 → 折りたたみ →
3.学習）で、道具としての構造になっていなかった。

直した点:

| 問題 | 対処 |
| ------ | ------ |
| デスクトップで横幅を使わず、縦に 1100px スクロールしても中身がない | 2 カラム化（左=映像、右=結果と学習）。狭い画面では 1 カラムに落とす |
| 開始方法が不明（ファイル選択・サンプル・カメラが同列） | 空状態に「カメラを開始 / 画像を選ぶ / サンプルで試す」を大きく出す |
| 「色順応補正（本体色アンカー）」等、普段触らない設定が最上部 | 「設定」の折りたたみへ移動 |
| ステータスが 4 つの span に散在 | 1 本の文に統合（`入力 ・ 検出 ・ 性能`） |
| 「?」が出る理由が分からない | 直下に理由を出す（「確信度 0.29 が低いため未確定（候補 4.7kΩ）」） |
| 副次操作（コピー・リセット）が主操作と同じ大きさ | 文字リンク相当に格下げ |
| 番号（1→2→3）の間に折りたたみが挟まり順序が壊れる | 番号を撤去し、タスク志向の見出しに |
| 入力をやり直せない | 「入力を変える」で空状態に戻す（学習データは保持） |

## Phase M0: 実機スモークテスト（最初にやる）

**計測せずに最適化しない。** `./doStart.sh` の URL を iPhone Safari と
Android Chrome で開き、以下を記録する。

- [ ] カメラ許可 → 映像 → 検出枠の表示まで通るか
- [ ] 実効 fps と 1 フレームの処理時間（画面上部に表示される）。
      落ちるようなら解析解像度が自動で下がるので、その値も記録する
- [ ] 発熱・電池の体感
- [ ] 値入力 → 学習 → localStorage 永続化（リロード後も残るか）
- [ ] 写真読み込み 3 経路: その場で撮影 / ギャラリー / HEIC 原本
- [ ] クリップボードコピーの可否（iOS はジェスチャ制約が厳しい）
- [ ] タブ切替・スリープ復帰後にカメラが再開するか
- [ ] 縦持ち・横持ちでのレイアウト崩れ

結果を本ドキュメントに追記し、M1 以降の優先度を決める。

## Phase M1: モバイルレイアウト（実装済み）

縦一列のカード構成に再編した。上から「入力 → 読み取り結果 → 値で学習」で、
詳細（ROI・1D プロファイル・バンド表・正解ラベル）は `<details>` に畳んだ。

- 640px 以下で専用レイアウトに切り替わる
- タップターゲットは 44px 以上（実測 44px）
- 読み取り結果は本文と画面下部バーの両方に出す
- 学習ボタンは下部の固定バー（親指圏）。値が空ならまず入力欄へ誘導する
- バンド表は横スクロールさせ、本文は横に溢れさせない
- `viewport-fit=cover` + `env(safe-area-inset-bottom)` でホームバーを避ける

## Phase M2: タッチ操作と細部（実装済み）

- `#source-canvas` に `touch-action: none`（ROI ドラッグとページスクロールの
  競合解消）
- クリップボード失敗時は選択可能なテキスト表示に落とす。iOS Safari は
  ユーザー操作の文脈から外れると `writeText` を拒否するため、
  「コピーできない」で終わらせず必ず取り出せる経路を残す
- Screen Wake Lock（`debug/wakeLock.ts`）。非対応・拒否でも黙って続行する
- `visibilitychange` で復帰時に Wake Lock を取り直し、止まった映像を再開する

## Phase M3: 性能

### M3.1 適応スロットリング（実装済み）

`debug/frameBudget.ts`。端末差が大きく事前に決め打ちできないので、
処理時間を実測して自動調整する。

- 落とす順序は **fps を先、解像度を後**。解像度は色帯の分離能力に直結する
  （設計メモ §2 [3]）ので最後まで守る。戻すときは逆順
- 解析解像度は 800 → 600 → 440 → 320px の 4 段
- 予算の 1.2 倍を超えたら劣化、0.5 倍を下回れば回復。変更後は
  12 フレームのクールダウンを置いて振動を防ぐ
- 状態は純粋関数で扱い、単体テスト 14 件で劣化・回復・安定域を固定

### M3.2 Worker 化（M0 の計測待ち）

適応スロットリングでも体感が悪い場合に踏み込む。ロードマップ Phase 1 の
前倒しで、core/ は DOM 非依存に保ってあるので移設は素直。

## Phase M4: ライブプレビューとオーバーレイ（✅ 実装済み 2026-07-31）

従来は「解析済みフレームを canvas に貼り直す」構成だった。しかも live 経路は
`setSource()` を通らず `#source-canvas` が hidden のままで、実質プレビューが
表示されていなかった（潜在バグ）。本来の構成に切り替えて根治した:

- `<video>` を直接表示（なめらかなプレビュー）— `debug/camera.ts` に
  `videoElement` オプションを追加し、DOM 上の `#live-video` を使う
- その上に `position: absolute` の透明 canvas（`#overlay-canvas`）で
  検出枠・バンド・読み値を重ねる。canvas の内在解像度を毎描画で解析
  フレームに合わせるため、検出座標を変換なしで描ける
- 座標変換（内在解像度 ↔ CSS 表示座標）は `debug/viewMapping.ts` に集約
  （設計メモ §2 [6] の注意そのまま）
- 検出枠の時間平滑化は `debug/boxSmoother.ts`（移動平均 + 倍角ベクトルの
  角度平均 + ジャンプ検出 + 検出途切れの保持）。平滑枠は描画専用で、
  色帯解析は生の検出枠を使う

あわせて UI の既定をカメラにした:

- ロード時に自動で `getUserMedia`（secure context のみ）。拒否・カメラ
  なしは空状態にフォールバックし、選択ボタンから静止画も選べる
- 画面モードは `idle / live / still` の状態機械（`applyMode`）で一元管理
- トーチ・ズーム・接写（超広角レンズ切替）のボタンを capability に応じて
  表示（`debug/cameraControls.ts` / `cameraControlsView.ts`。
  41-QR-search の録画画面から移植）。非対応端末では出ない
- ライブ中はカメラアプリのような全画面表示（`body.live` の CSS のみで
  切替）。映像は object-fit を使わずアスペクト保存の制約解決で画面いっぱい
  に拡大し、ボタン・推測値・ステータスを映像上にオーバーレイする

## Phase M5: PWA 最小対応（任意）

- manifest + アイコンで「ホーム画面に追加」できるようにする
- オフラインキャッシュはロードマップ Phase 4 で本格対応（今回はスコープ外）
- **注意**: 権限・ストレージはオリジン単位（設計メモ §8）。`*.ts.net` の
  URL で PWA 化しても本番ドメインには引き継げない。暫定と明記して運用する

## リスク

| リスク | 備え |
| -------- | ------ |
| iOS のメモリ制限（HEIC WASM 3MB + 高解像度画像）でタブが落ちる | M0 で確認。落ちるなら HEIC 変換後に即解放・画像の縮小を前倒し |
| 手持ち撮影のブレで自動検出が暴れ、学習の対応付けが不安定 | M4 の平滑化を前倒しするか、「この画で止める」を学習の推奨経路にする |
| iOS Safari の getUserMedia がジェスチャ文脈以外で失敗 | ロード時の自動起動が失敗したら空状態へ落とし、再試行は必ずボタンタップから |
